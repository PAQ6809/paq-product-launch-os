# PAQ Product Launch OS MVP 範圍

## MVP 目標

第一版目標是驗證「使用者輸入商品資料後，系統能產出結構完整、可審核、可修改、可匯出的商品上市報告」。MVP 應優先把資料模型、使用流程、報告結構與審核邏輯做穩，不追求一次完成所有平台整合或真實自動化。

## MVP 必做功能

1. 商品專案建立
   - 使用者可以建立新商品專案。
   - 專案至少包含商品名稱、商品類別、銷售平台與建立時間。

2. 商品資料輸入表單
   - 支援輸入商品功能、成本、預計售價、目標客群、品牌風格、商品規格與注意事項。
   - 表單可儲存草稿。

3. 商品圖片上傳與預覽
   - 支援至少一張商品圖片。
   - 圖片可在專案頁中預覽。
   - 第一版不需要圖片 AI 分析，但資料結構需保留圖片欄位。

4. Mock AI workflow
   - 使用本地 mock 邏輯或固定模板生成完整上市報告。
   - 輸出必須包含 20 個指定報告區塊。
   - 每個區塊需要有標題、內容、狀態與風險提示欄位。

5. 報告檢視頁
   - 使用者可以瀏覽完整報告。
   - 報告需以區塊呈現，方便逐段審核。

6. 報告編輯
   - 使用者可以修改每個報告區塊的內容。
   - 修改後需保存結果。

7. 審核狀態
   - 每個區塊支援待審核、已修改、已通過三種狀態。
   - 高風險區塊需顯示人工審核提示。

8. Markdown 匯出
   - 使用者可以匯出完整上市報告為 Markdown。
   - 匯出內容需包含商品基本資料與 20 個報告區塊。

## MVP 可以簡化的功能

- 使用單一使用者模式，不做登入與權限。
- 使用本地資料庫或簡單後端儲存，不先做正式雲端架構。
- AI 產出先用 mock workflow，不先接真實 API。
- 競品分析可以先要求使用者手動輸入競品資訊，不做自動爬蟲。
- 圖片只做上傳與預覽，不做背景移除、修圖或生成包裝圖。
- 匯出先做 Markdown，不先做 PDF 或 Google Docs。

## MVP 不做功能

- 不直接串 Shopify、Amazon、蝦皮或其他電商平台上架。
- 不自動投放廣告。
- 不自動產生可直接商用的包裝設計圖。
- 不保證 AI 生成內容合法、合規或可商用。
- 不保證商品會賣爆或達到特定銷售結果。
- 不處理金流、物流、庫存與訂單管理。
- 不做多人協作與權限管理。
- 不做競品價格即時追蹤。
- 不做正式商標查詢或法務審查。

## MVP 驗收標準

1. 使用者可以從空白狀態建立一個商品專案。
2. 使用者可以填寫商品資料並上傳圖片。
3. 系統可以產生包含 20 個區塊的商品上市報告。
4. 使用者可以修改任一報告區塊。
5. 使用者可以切換任一報告區塊的審核狀態。
6. 使用者可以匯出 Markdown 報告。
7. 報告中所有高風險內容都應提示需要人工審核。

## MVP 成功後再進入的下一階段

- 建立正式資料庫 schema
- 串接真實 AI API
- 加入圖片理解能力
- 加入 PDF 匯出
- 加入平台格式模板
- 加入商業化 landing page 與 demo flow
