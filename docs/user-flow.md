# PAQ Product Launch OS 使用者流程

## 流程總覽

使用者從建立商品專案開始，依序完成商品資料輸入、圖片上傳、品牌與平台設定、AI 產出報告、人工審核與匯出。第一版流程應該讓使用者即使沒有完整商品企劃經驗，也能按照畫面引導完成一份可討論的上市報告。

## 1. 進入系統

使用者開啟 PAQ Product Launch OS 後，看到商品專案列表與建立新專案按鈕。

使用者可以：
- 建立新商品專案
- 開啟既有商品專案
- 查看每個專案的狀態，例如草稿、已生成、審核中、已完成

## 2. 建立商品專案

使用者點擊建立新專案後，系統要求填寫最基本的商品資訊：

- 商品名稱
- 商品類別
- 商品目前階段，例如概念、樣品、已量產、準備上架
- 主要銷售平台

系統建立專案後，使用者進入商品資料輸入頁。

## 3. 上傳商品照片

使用者上傳一張或多張商品照片。第一版只需要保存圖片並顯示預覽，不需要做圖片生成或圖片編修。

圖片用途：
- 協助使用者確認專案內容
- 未來可交給 AI vision model 做外觀、包裝與視覺風格分析
- 作為包裝 brief 與商品頁內容的參考資料

若使用者沒有圖片，系統仍允許先建立文字版報告，但需要提示「缺少圖片時，包裝與視覺建議準確度會下降」。

## 4. 填寫商品資料

使用者填寫商品上市所需欄位：

- 商品功能
- 商品特色
- 成本
- 預計售價
- 目標客群
- 品牌風格
- 商品規格
- 使用方式
- 禁忌或注意事項
- 競品名稱或參考連結

表單應允許部分欄位空白，但在生成報告前需要提醒哪些欄位會影響輸出品質。

## 5. 選擇輸出設定

使用者選擇報告偏好：

- 語氣：專業、年輕、精品、溫暖、極簡、科技感
- 銷售平台：自架官網、Shopify、蝦皮、Amazon、Pinkoi、momo、社群私訊
- 文案長度：精簡、標準、詳細
- 目標市場：台灣、香港、日本、美國或其他市場

第一版可以先把這些設定當成 mock workflow 的輸入，不一定要全部影響生成結果，但資料結構必須先保留。

## 6. 生成上市報告

使用者點擊生成報告後，系統進入處理狀態。第一版可以用 mock AI workflow 模擬處理，不需要先接真實 AI API。

處理畫面應顯示主要步驟：

1. 整理商品資料
2. 分析目標客群
3. 產出定位與賣點
4. 產出商品頁與社群文案
5. 產出 FAQ、客服話術與行銷計畫
6. 組合完整報告

完成後，使用者進入報告檢視頁。

## 7. 檢視報告

報告以區塊方式呈現，每個區塊對應一個輸出項目。例如商品定位、競品分析、定價建議、包裝 brief、商品頁描述、短影音腳本等。

每個區塊應包含：

- 區塊標題
- AI 產出的內容
- 狀態標籤：待審核、已修改、已通過
- 編輯按鈕
- 風險提醒或人工審核提示

高風險區塊，例如定價、食品美妝功效、醫療保健宣稱、商標與平台規則，需要顯示較明顯的審核提示。

## 8. 修改與審核

使用者可以逐段修改內容。修改後，該區塊狀態變成已修改。使用者確認內容可用後，可以標記為已通過。

第一版不需要做多人審核，但資料結構應保留區塊狀態，方便未來加入團隊協作。

## 9. 匯出報告

使用者完成審核後，可以匯出完整報告。

第一版匯出目標：
- Markdown
- 可複製的純文字

後續版本可加入：
- PDF
- Google Docs
- Shopify 商品草稿
- 設計 brief 檔案
- 社群排程格式

## 10. 後續優化

使用者上市後，可以回到專案補充銷售表現，例如點擊率、轉換率、退貨原因、客服常見問題與顧客評論。

未來系統可根據這些資料重新產出：
- 商品頁優化建議
- FAQ 更新建議
- 價格調整建議
- 社群素材主題
- 包裝或賣點修正方向

第一版只需要在報告中產出「銷售後優化建議」，不需要真的接銷售資料。
